# Make Backed Mode acknowledgement policy configurable

Backed Mode uses the Strict Policy by default in production packages: both writes must reach a terminal result before reporting, and a successful Backing Store write may preserve the request as Local-Only Data when its RDMA write fails. Operators may explicitly select the Remote-First Policy, which reports a write after the Remote Memory write completes and the Backing Store write has been submitted, preserving the original system's latency behavior while accepting a delayed backing-error window. The policy is selected when an Infiniswap Device is created and cannot change while it is online. A late Backing Store failure under Remote-First moves the device to Backing-Degraded, rejects new writes, and requires the device to be stopped and recreated after storage is repaired.
