# Commit Remote-Only capacity

A Remote Chunk assigned to a Remote-Only Mode device is a non-evictable capacity commitment from its Memory Provider for as long as the device uses it. A Provider exposes three explicit capacity controls: Host Reserve, maximum Opportunistic Pool capacity for Backed Mode, and maximum Committed Pool capacity for Remote-Only Mode. The pools have separate accounting and the Committed Pool is never overcommitted. Once admitted, a commitment takes priority over later Provider-local memory demand; the operator must size Host Reserve and pool limits to protect local workloads. If any Provider holding data for a Remote-Only Device is lost, the entire device enters Remote-Lost rather than continuing with partially valid address ranges. Cross-Provider migration or replication may later permit safe reclamation and failure tolerance without adding a Backing Store.
